# NNNN: Short imperative title

Status: proposed | accepted | superseded
Date: YYYY-MM-DD

## Context

What forced a decision. Constraints that were real at the time, including the ones that were
about time, money or taste rather than engineering. Enough that a reader a year from now does
not have to reconstruct the situation.

## Decision

What was chosen, stated so that a reader can tell whether the current code still follows it.

## Alternatives considered

Each one that was genuinely on the table, and the specific reason it lost. An alternative
dismissed without a reason will be proposed again.

## Consequences

What this makes easy, what it makes hard, and what has to be revisited if an assumption
changes. Include risks accepted deliberately — an accepted risk that is not written down
becomes a surprise.

## Acceptance criteria

Only when this record came out of a design cycle. Each criterion carries how it is
checked, because a criterion nothing can check is a sentence rather than a requirement.

- [ ] What must be true.
      check: a command that FAILS when this is violated
- [ ] What no command can observe.
      manual: the action → evidence: where it is recorded
