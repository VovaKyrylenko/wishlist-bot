# Флоу бота — повний опис

Карта всього, що користувач може зробити: точки входу, екрани, переходи, сповіщення та фонові задачі. Складено з коду (`src/features/*`, `src/lib/*`, `api/*`), тексти — з [src/text.ts](../src/text.ts).

Концепція, з якої це виросло, — [UX-REDESIGN.md](UX-REDESIGN.md). Посилання на кшталт «§8.4» або «R5» ведуть саме туди.

---

## 1. Точки входу

| Вхід | Файл | Що робить |
|---|---|---|
| Telegram webhook | [api/webhook.ts](../api/webhook.ts) | `POST /api/webhook`, перевірка `x-telegram-bot-api-secret-token`, ідемпотентність по `update_id`, далі `bot.handleUpdate` |
| Годинний крон | [api/cron.ts](../api/cron.ts) | `0 * * * *` ([vercel.json](../vercel.json)): нагадування про подію, дайджест тим, хто стежить, чистка |
| Локальний polling | [scripts/dev-polling.ts](../scripts/dev-polling.ts) | Те саме, але без вебхука |

**Ідемпотентність webhook.** `update_id` спершу «claim»-иться вставкою в `ProcessedUpdate`. Дубль (Telegram ретраїть повільні відповіді) → `200 {duplicate:true}` без обробки. Якщо обробка впала — claim знімається і повертається `500`, щоб Telegram переслав апдейт ще раз.

## 2. Три правила, з яких випливає решта

1. **Один якір.** Reply-клавіатура має рівно одну кнопку `🏠 Головна` ([src/lib/keyboards.ts](../src/lib/keyboards.ts)). Вона працює звідусіль. Посеред незавершеної дії — це безпечний вихід: чернетка видаляється, питання знімається, екран прямо каже «Скасував — нічого не збережено».
2. **Один живий екран.** `User.screenMessageId` пам'ятає, яке повідомлення зараз є екраном. Тап, що прийшов *із* нього, редагує його на місці; тап із будь-чого старішого малює **свіжий екран унизу чату**, не чіпаючи старе повідомлення ([src/lib/screen.ts](../src/lib/screen.ts)).
3. **Ввід завжди валідний.** `bot.on("message")` існує і ніколи не мовчить.

**Немає conversations.** Питання — це запис `pendingAction` на користувачі ([src/lib/pending.ts](../src/lib/pending.ts)): `<домен>.<поле>[:<id>]`, живе 24 години. Наступне звичайне повідомлення стає відповіддю; будь-який тап по кнопці **знімає** питання (middleware в [src/bot.ts](../src/bot.ts)), інакше текст, написаний через годину, зарахувався б у відповідь на давно покинуте питання.

## 3. Ролі

| Роль | Як стає | Що може |
|---|---|---|
| **Власник** (`Wishlist.ownerId`) | створив список | усе |
| **Співавтор** (`WishlistEditor`) | прийняв одноразове запрошення | подарунки (додати/правити/порядок/видалити) і «Поділитися». **Замість кнопки «Про список» — рядок «👥 Ти співавтор цього списку»** — кнопки-обманки немає взагалі (§9.10) |
| **Гість** | відкрив список за посиланням | перегляд, обіцянка, стежити, поділитися |

Перевірка — [`lookupList`](../src/lib/access.ts) + `requireList` у [lists.ts](../src/features/lists.ts). Відмова **ніколи не є алертом**: список зник → Головна з рядком «Цей список більше не існує…»; немає доступу → Головна з «Цей список ведуть без тебе 🙂»; співавтор постукав у «Про список» → екран списку з поясненням «налаштування змінює власник».

## 4. `/start` і deep links

```
/start [payload]
├─ list_<slug> → вітрина (§9). Слаг не знайдено → Головна + «Це посилання більше не діє»
├─ ed_<token>  → екран «{Ім'я} запрошує тебе разом вести список «{Назва}»» [Приєднатися]
│                 (приймається окремим тапом — перехід за лінком не роздає доступ мовчки)
├─ res_<id>    → «🎗 Я дарую»
└─ без payload → чернетка з вмістом? «Продовжити?» : дайджест (§11) + Головна
```

Перший екран будь-якої людини випереджає одноразова підказка «Знизу з'явилася кнопка 🏠 Головна…» з самою клавіатурою. Ознака «ще не бачив» — `screenMessageId IS NULL`, окремого прапорця немає.

### Команди

| Команда | Поведінка |
|---|---|
| `/start` | див. вище |
| `/home`, `/menu` | те саме, що якір: скасувати поточне й показати Головну |
| `/help` | коротка шпаргалка екраном (не стіна тексту) |
| `/cancel` | синонім до `/home` — виходити більше немає звідки |

Невідома команда (`/foo`) **не** пропонується як подарунок — іде у м'який fallback.

## 5. Розумний ввід (F3)

`bot.on("message")` в [entry.ts](../src/features/entry.ts), по порядку:

```
1. текст == «🏠 Головна»        → скасувати все + Головна
2. є відкрите питання           → це відповідь на нього
   └─ питання «draft.input»     → класифікувати як подарунок у вже відомий список
3. дайджест після паузи (§11)
4. у тексті є URL               → чернетка з посилання (скрапінг)
5. фото                         → чернетка з фото; підпис = назва
6. є покинута чернетка з вмістом → «Ти не закінчив додавати «…». Продовжити?» [Продовжити] [Почати заново]
7. порожньо / «/…» / ввічливість / текст > 60 символів
                                → «Я бот для списків бажань 🙂» + Головна
8. короткий текст               → «Додати «…» як подарунок?» [Так, у «{список}»] [Ні, це не подарунок]
```

**Стоп-слова ввічливості** (§21.1): «дякую», «привіт», «ок», «супер», емодзі тощо — інакше бот відповідає «Додати "дякую" як подарунок?» і виглядає дурником. Порівнюється весь текст (до двох слів), не підрядок.

**Куди потрапляє подарунок:**

| Списків у людини | Поведінка |
|---|---|
| 0 | «Схоже на подарунок! Тільки списку ще немає — створимо перший?» Чернетка **зберігається** і чекає: щойно список створено, вона в нього і поїде |
| 1 | одразу в нього, заголовок картки каже, куди саме |
| 2+ | «🎁 Додаю подарунок. У який список?» + кнопки списків + «➕ Новий список» |

## 6. Чернетка та превʼю-картка (F2)

Подарунок збирається в `Draft` ([src/lib/drafts.ts](../src/lib/drafts.ts)) і стає `WishlistItem` **лише** на «✅ Додати». Одна чернетка на людину; нова замінює стару. Живе 24 години.

```
URL → екран «🔎 Дивлюся, що там…»
      ├─ 3 с    → той самий екран стає «🔎 Сайт відповідає повільно, ще секунду…»
      ├─ 8 с    → скрапер здається
      ├─ вдалося → превʼю-картка (фото, назва, ціна, магазин)
      └─ ні      → «Не зміг відкрити цей сайт 😕 Напиши назву — посилання я вже зберіг»
Фото → картка з фото; підпис = назва; без підпису → «Гарне фото! Що це за подарунок?»
Текст → картка з назвою

Картка:  [✅ Додати]  [✏️ Змінити щось]  [Скасувати]
«Змінити щось» → Назва · Ціна · Фото · Посилання · Магазин · Коментар · Кількість · Наскільки хочу
                  (+ «Прибрати фото», якщо воно є)
```

Прогрес і картка живуть **в одному повідомленні** — `replaceLiveScreen` переписує екран замість того, щоб класти три повідомлення поспіль.

Кнопка «Пропустити» є лише там, де порожнє значення осмислене (ціна, посилання, магазин, коментар). Назва обов'язкова, «0 штук» ніхто не має на увазі.

Поле «Посилання» приймає лише справжні адреси — голий `rozetka.com.ua/…` добудовується до `https://…`, а «у розетці» перепитується. Невалідний url зламав би кнопку «Де купити»: Telegram відхиляє всю клавіатуру, і екран мовчки не рендериться.

**Успіх** (§13: результат → де воно тепер → наступний крок):

| Умова | Текст | Кнопки |
|---|---|---|
| перший подарунок | «✨ «…» — перший подарунок у «…»!» | `➕ Ще один` · `📤 Поділитися` · `⬅️ До списку` |
| 2-й | «✅ «…» у списку «…»!» | те саме |
| 3-й і далі | «…Список уже виглядає готовим 👌 Час поділитися?» | **`📤 Поділитися` першою** |

Тим, хто стежить, звідси **нічого не надсилається** — про нові подарунки розповідає годинний дайджест (§12), інакше 20 подарунків за вечір = 20 пінгів.

**Скрапер** ([src/lib/scrape.ts](../src/lib/scrape.ts)): захист від SSRF (блок loopback/private/link-local/CGNAT, перевірка кожного редіректу, максимум 3 хопи), ліміт 2 МБ і 8 секунд.

Дані беруться пошарово — від найнадійнішого джерела до найгіршого, і кожне поле окремо:

| Поле | Порядок джерел |
|---|---|
| назва | JSON-LD `Product.name` → мікродані `itemprop=name` → `og:title` → `twitter:title` → `<h1>` → `<title>` |
| ціна | JSON-LD `Offer`/`AggregateOffer` → мікродані → `product:price:amount` → видимий DOM |
| фото | JSON-LD `image` → `og:image` → `twitter:image` → мікродані → `link[rel=image_src]` |
| магазин | `og:site_name` → JSON-LD `Organization` → домен |

**Назва.** Заголовок сторінки — це не назва товару. `ᐉ Сковорода Krauff • Краща ціна в Києві • Купити в Епіцентр` перетворюється на `Сковорода Krauff`: знімаються декоративні префікси, хвости з назвою магазину і SEO-хвости («купити», «ціна», «відгуки»). Дефіс усередині моделі (`WH-1000XM6`) недоторканий. Якщо бренд відомий, а в назві його немає — він стає попереду: `WH-1000XM6` → `Sony WH-1000XM6`.

**Ціна** ([src/lib/price.ts](../src/lib/price.ts)) завжди зводиться до одного вигляду: `12 999 ₴`, `24,90 €`, `199 zł`. Розділювач визначається за правилом price-parser: після останньої крапки чи коми **три цифри — це тисячі** (`12.999` = 12 999), одна, дві або 4+ — копійки (`12.99` = 12,99). Валюта впізнається за символом (`₴ $ € £ zł`), ISO-кодом і словом («грн», «доларів», «євро»). Якщо поруч кілька чисел — виграє **менше**: і акційна ціна поруч із перекресленою, і нижня межа діапазону — це те, за скільки подарунок реально можна взяти. У DOM ціна береться лише там, де валюта написана явно, повз перекреслені блоки й «доставка / кредит / за міс.».

**Зберігається двічі.** `WishlistItem.price` (і `Draft.price`) — завжди вихідний текст, який показує картка: «12 999 ₴», але так само чесно і «від 2 000 грн», і «домовимось», якщо саме так написав власник чи знайшов скрапер. `priceAmount`/`priceCurrency` заповнюються `structurePrice()` **лише коли текст читається як чисте число** — це підготовка під майбутнє сортування чи фільтр за ціною, а не заміна показу. Ручне редагування поля «Ціна» проходить той самий розбір, що й скрапінг: власник, що впише «2 450 грн», отримає ті самі структуровані поля, що й лінк на той самий товар. Очищення поля скидає обидва структуровані поля разом із текстом.

**Кодування.** Багато українських магазинів досі віддають windows-1251. Кодування читається із заголовка або з `<meta charset>` — інакше назва подарунка перетворювалась на `Íàóøíèêè`.

Перевіряється це набором фікстур: `npm run verify:scrape` ([scripts/scrape/](../scripts/scrape/)) — JSON-LD, `@graph` з `AggregateOffer`, мікродані, самий OpenGraph, сторінка без розмітки зі старою ціною поруч, cp1251, поламаний JSON-LD, граничні випадки назв і валют. Бази даних не потребує.

> ⚠️ Частина великих магазинів (Rozetka, IKEA) відповідає `403`/`401` на серверний запит незалежно від розмітки. Для них лишається звичайний шлях: «Не зміг відкрити цей сайт — напиши назву, посилання я вже зберіг».

## 7. 🏠 Головна (S2)

```
🏠 Головна

🎁 Твої списки
1. 🎂 День народження
    15 серпня · через 12 днів · 12 подарунків

🎗 Ти даруєш: 2 подарунки
👀 Списки друзів: 3
```

Сортування: найближча подія вгорі, потім списки без дати (новіші перші). 8 на сторінку.

Кнопки: номери → пагінатор → `➕ Новий список` → `🎗 Я дарую` (+ `👀 Списки друзів`, якщо є) → `🏁 Завершені (N)` (якщо є) → `⚙️ Про мене`. Розділи без вмісту кнопки не отримують — двері в порожню кімнату нікому не потрібні.

Порожня Головна для абсолютно нової людини — це **онбординг** (S1): одне речення цінності й одна кнопка `➕ Створити список`.

### Створення списку

Одне питання, і на 80 % випадків відповідають пресети: `🎂 День народження` · `🎄 Новий рік` · `💍 Весілля` · `✏️ Своя назва`. Опис, дата й режим сюрпризу мають дефолти й живуть у «Про список».

### ⚙️ Про мене (S9)

Ім'я, кількість списків і обіцянок, блок «Що бачать інші» простою мовою. Кнопки: `❓ Як це працює`, `🗑 Видалити збережений номер` (лише якщо номер лишився з часів, коли бот його питав), `🗑 Видалити всі мої дані` (з підтвердженням і переліком того, що зникне).

## 8. Список власника

### S3 — екран списку

Шапка → статус → подарунки → дії. `📅 15 серпня · через 12 днів` — дата по-людськи. Для співавтора — рядок «👥 Ти співавтор цього списку».

**Пульс** (§8.4) — рівно стільки, щоб відчути, що список працює, і не більше:

| Режим сюрпризу | Обрано | Що бачить власник |
|---|---|---|
| увімкнено | 0 | нічого |
| увімкнено | ≥1, подарунків < 4 | «🎉 Список живий — друзі вже заглядають» |
| увімкнено | ≥1, подарунків ≥ 4 | «🎉 Друзі вже обрали 3 з 12 подарунків» |
| вимкнено | ≥1 | «👀 Обрано 3 з 12» + кнопка `👀 Хто що дарує` |

Порожній список: «Додай перший подарунок — просто надішли мені посилання, фото або назву 🙂» — головна дія тут **сам ввід**, не кнопка.

Кнопки: номери → пагінатор → `➕ Додати подарунок` → `📤 Поділитися` + `⚙️ Про список` (лише власник) → `⬅️ Головна`. Для завершеного списку замість додавання — `🔄 Використати знову` і `↩️ Повернути в активні`. Завершений список не приймає подарунків навіть зі старих кнопок «Додати» — і `it:add`, і збереження чернетки перевіряють статус і відповідають «Список завершено…».

### S4 — екран подарунка

`🎂 День народження › <b>Навушники</b>` — заголовок завжди каже, де ти. Ціна · магазин, коментар, кількість (якщо > 1), «наскільки хочеш» (лише якщо не дефолт). **Жодного натяку на обіцянки, поки сюрприз увімкнено** — включно з лічильниками.

Кнопки: `🔗 Де купити` → `✏️ Змінити` → `⬆️ Вище`/`⬇️ Нижче` → `⏫ Зробити першим` (з 3-ї позиції) → `🗑 Видалити` → `⬅️ Назад`. Видалення стоїть окремо, ніколи поруч із «✏️» (§15.3).

### S6 — поширення

Превʼю «ось що побачить друг», посилання в `<code>` (тап — і воно скопійоване), `📨 Надіслати другу` (`switch_inline_query`), `👥 Запросити співавтора`. Порожній список спершу попереджає: «Список поки порожній — друзі побачать пустку» `[➕ Додати подарунок] [Все одно поділитися]`.

### S7 — про список

Один плоский екран без піддерев: назва, опис, дата, режим сюрпризу, сповіщення, співавтори, закрити старе посилання, завершити, видалити.

| Дія | Поведінка |
|---|---|
| `📅 Дата` | розуміє «15 серпня», «12.08.2026», «12.08», «завтра». Не розпізнав — перепитує з прикладами, а не здається. Підтверджує словами: «✅ Зберіг: 25 грудня». Скидає `reminderSentAt` |
| `🤫 Сюрприз` | **вимкнення — з попередженням** про наслідок для друзів; вмикання назад — миттєво |
| `🔔 Сповіщення` | тумблер `notifyOwner` |
| `🔗 Закрити старе посилання` | підтвердження → новий `slug`; нове посилання показане одразу |
| `🏁 Завершити` | підтвердження → `ARCHIVED` → DM кожному, хто щось обіцяв → список їде в «Завершені» |
| `🔄 Використати знову` | копія з подарунками, **без обіцянок**, з нульовою датою |
| `🗑 Видалити` | **два кроки** (§R9): «Відновити буде неможливо» → «Так, видалити список і 12 подарунків» → DM гостям → каскад → Головна |

### Співавтори

Список по 10, тап по номеру прибирає доступ **миттєво, з `↩️ Повернути`** в тому самому екрані. Запрошення одноразове: токен обнуляється в момент прийняття, тож переслане посилання нікого більше не впустить.

## 9. Вітрина гостя (S5)

```
🎂 День народження
Список бажань · Марта          ← ім'я в називному, завжди (див. CLAUDE.md)
📅 15 серпня · через 12 днів

Обери подарунок — Марта не побачить, що саме ти вибрав 🤫

1. 🔥 Навушники Sony
    12 999 ₴
2. Худі оверсайз
3. Kindle
    ✅ вже дарують
```

Сортування: **спершу вільні**, всередині — за «наскільки хочу». Понад 15 подарунків із зайнятими — автоматично вмикається «Сховати зайняті» (§15.9). Кожен рендер пише `WishlistVisit` — саме це дає гостю шлях назад без обіцянки й стеження.

Режим сюрпризу на гостя не впливає: він завжди бачить, що вже зайняте. Сюрприз ховає інформацію **тільки від власника**. Якщо власник сюрприз вимкнув, гостя чесно попереджають до вибору: «⚠️ У цьому списку сюрприз вимкнено: Марта бачить, хто що обрав».

**Вітрина — тільки для гостей.** Власник або співавтор, що відкрив власне share-посилання (чи будь-яку кнопку `g:*`), потрапляє на свій екран списку — інакше позначки «вже дарують» на вітрині обходили б контракт сюрпризу через власне ж посилання. З цієї ж причини інсайдер не може ані обіцяти подарунок у своєму списку, ані стежити за ним.

### S5a — подарунок гостя і обіцянка (G3)

`🎁 Я подарую це` → **миттєвий успіх, без кількостей, контактів і підтверджень**:

> Домовились! 🤝
> «Навушники Sony» — за тобою. Марта не дізнається 🤫
> Знайдеш це в «🎗 Я дарую» на Головній.
> `[↩️ Передумав]` `[⬅️ До списку]`

Запис іде в `SERIALIZABLE`-транзакції: read-then-write на доступності — саме той патерн, де read-committed дає двом гостям виграти одночасно. Повторна обіцянка того самого гостя **зливається** в один рядок (`+1`). Програв гонку — «Ой, щойно цей подарунок узяв хтось інший 😔» і одразу перелік вільного (G7). Подарунок повністю зайнятий → кнопки обіцянки немає взагалі, є `🔔 Повідомити, якщо звільниться`.

**«↩️ Передумав» відкочує один тап — одну штуку.** Гість, що взяв одну раніше й додав «+1 ще», відмовляється від +1, а не від усього. Кнопка зі старого екрана успіху спершу перевіряє статус: куплену обіцянку вона не чіпає (відправляє в «🎗 Я дарую»), скасовану — чесно каже, що нічого не змінює. Власник отримує те саме сповіщення, що й при «Відпустити», а якщо подарунок був розібраний повністю — тим, хто стежить, іде «знову вільний».

## 10. 🎗 Я дарую (S8)

Обіцянки згруповані за списками, найближча подія вгорі — людина стоїть у магазині й питає «що я обіцяв?».

```
🎗 Ти даруєш 3 подарунки

🎁 🎂 День народження · 15 серпня
1. Навушники Sony — обіцяно
2. Худі — ✅ куплено
```

| Дія | Вага | Чому саме така |
|---|---|---|
| `✅ Я вже купив` | миттєво | обіцянка самому собі; поруч одразу видно, як відкотити |
| `↩️ Ще не купив` | підтвердження | власнику вже сказали «щось куплено» — тож після підтвердження йому йде сповіщення, що позначку знято |
| `💨 Відпустити` | підтвердження | зачіпає інших: подарунок повернеться у вільні |
| `💨 Відпустити` після «куплено» | **суворіше** підтвердження | «Ти вже позначав його купленим… вийде дублікат» |

Відпущений подарунок, який був розібраний повністю, **одразу** тригерить DM тим, хто стежить, — це рідка й термінова подія, заради якої на список і підписуються.

## 11. Повернення після паузи (F6)

7+ днів тиші → перед Головною йде окреме повідомлення-дайджест:

```
З твого минулого візиту:
🎉 у «День народження» друзі обрали 2 подарунки
📅 подія «День народження» вже через 5 днів
🎗 ти обіцяв подарунок у «Список Олега» — не забудь 🙂
```

Порівняння йде з `User.previousSeenAt` (`lastSeenAt` оновлюється не частіше разу на годину, щоб не писати рядок на кожне натискання). Рядок про обрані подарунки підпадає під контракт сюрпризу: при увімкненому сюрпризі показується лише якщо в списку ≥ 4 подарунків. Нічого не змінилось — дайджесту немає взагалі.

## 12. Сповіщення

Усі DM ідуть через [`safeSend`](../src/lib/notify.ts): тротлінг (≥40 мс між надсиланнями). Якщо Telegram каже «заблокований / чат не знайдено» — у людини видаляються лише стеження (push-канал); історія переглядів, списки й обіцянки лишаються, бо людина може розблокувати бота і повернутись. `safeSend` розрізняє три результати: доставлено · назавжди недосяжний · тимчасовий збій.

### Власнику (усе глушиться тумблером `notifyOwner`)

| Подія | Сюрприз увімкнено | Вимкнено |
|---|---|---|
| Нова обіцянка | «друзі обрали ще один подарунок. Який саме — не кажу 🤫» | подарунок + хто + кількість |
| Обіцянку відпущено | «один подарунок знову вільний» | подарунок |
| Позначено «куплено» | «один із подарунків уже куплено 🤫» | подарунок + хто |
| Знято позначку «куплено» | «один подарунок знову "обіцяно, але ще не куплено"» | подарунок + хто |
| Приєднався співавтор | завжди, незалежно від режиму | те саме |
| Нагадування за 3 дні | завжди | те саме |

### Гостю — усе, що ламає його обіцянку

| Подія | Текст |
|---|---|
| Подарунок прибрали | «…Твоя обіцянка скасована» / для купленого — «позначку я зберіг» |
| Подарунок повернули (undo) | «…твоя обіцянка знову діє 🙂» |
| Список завершено | «Твоя обіцянка лишається в силі — просто нових подарунків там уже не оберуть» |
| Список видалено | «Твоя обіцянка там більше не діє» |

### Тим, хто стежить

| Подія | Коли |
|---|---|
| Подарунок знову вільний | **миттєво** |
| Нові подарунки | **дайджест раз на годину**, одне повідомлення на список |

## 13. Крон

Авторизація: `Authorization: Bearer $CRON_SECRET`. У проді відсутній `CRON_SECRET` → `500` (fail-closed), локально ендпоінт відкритий.

1. **Нагадування про подію** за 3 дні. Отримувачі: ті, хто стежить ∪ ті, хто переглядав, мінус власник; плюс власник, якщо `notifyOwner`. `reminderSentAt` гарантує одне нагадування на дату.
2. **Дайджест нових подарунків** для кожного стеження на активному списку. Ватермарка `lastNotifiedAt` зсувається після доставки або якщо людина назавжди недосяжна; **тимчасовий збій** (таймаут, 429) лишає її на місці, і наступний запуск повторює саме цей дайджест замість того, щоб втратити його назавжди.
3. **Чистка `ProcessedUpdate`** старших за добу.
4. **Чистка чернеток і покинутих питань** старших за добу.

## 14. Відновлення після помилок (§16)

| Ситуація | Поведінка |
|---|---|
| Тап по старій кнопці | мовчазний ререндер актуального екрана внизу чату |
| Невідомий `callback_data` (старий деплой) | мовчки Головна. Фрази «ця кнопка застаріла» в продукті **немає** |
| Сутність зникла | Головна + рядок «Цей список більше не існує — власник його видалив» |
| Кинута дія | чернетка 24 год → «Продовжити?» при наступному контакті |
| Незрозумілий ввід | класифікація (§5), у найгіршому разі — «ось Головна», ніколи мовчання |
| Гонка при обіцянці | чесне пояснення + одразу перелік вільного + «стежити» |
| Внутрішня помилка | «Щось пішло не так у мене 😔 …усе, що ти зберігав раніше, ціле» + Головна (`bot.catch`) |
| Випадкове видалення подарунка | undo 5 хв, разом з обіцянками, які воно зламало |
| Випадкове видалення списку | два кроки підтвердження, undo немає — і про це сказано прямо |

## 16. Що перевіряється автоматично

`npm run verify:flows` ([scripts/flows/](../scripts/flows/)) проганяє бота синтетичними апдейтами й перевіряє не «не впало», а самі правила: сповіщення власнику не називає подарунок, стара кнопка не отримує «застаріла», покинуте питання знімається, undo повертає й подарунок, і зламані ним обіцянки, співавтор не бачить кнопки-обманки. Деталі запуску — у [README](../README.md#перевірка-флоу).
